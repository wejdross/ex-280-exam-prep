# Task 06 — Edge-terminated route

## oc path

```bash
oc new-project ex280-t06
oc create deployment edge-app --image=quay.io/redhattraining/hello-world-nginx:latest --replicas=1
oc expose deployment edge-app --port=8080 --target-port=8080 --name=edge-app

oc create route edge edge-app \
  --service=edge-app --port=8080 \
  --hostname=edge-app.apps-crc.testing \
  --cert=assets/edge-app/tls.crt \
  --key=assets/edge-app/tls.key \
  --insecure-policy=Redirect
```

The cert and key are pre-generated in `assets/edge-app/`. Don't run `openssl` — the real exam
hands you the files.

Note `oc expose deployment` creates a **Service**; `oc expose service` creates a **Route**.
Same verb, different output, depending on what you point it at. Here we need the Route to carry
TLS material, so it's `oc create route edge` rather than `oc expose service`.

## YAML path

```yaml
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: edge-app
  namespace: ex280-t06
spec:
  host: edge-app.apps-crc.testing
  to:
    kind: Service
    name: edge-app
  port:
    targetPort: 8080
  tls:
    termination: edge
    insecureEdgeTerminationPolicy: Redirect
    certificate: |
      -----BEGIN CERTIFICATE-----
      ...
    key: |
      -----BEGIN PRIVATE KEY-----
      ...
```

The PEM blocks must be inline and indented. This is exactly why `oc create route edge
--cert/--key` is the better path under time pressure.

## The three terminations

| Termination | Client→router | Router→pod | Cert lives |
|---|---|---|---|
| `edge` | TLS | **plain HTTP** | on the Route |
| `passthrough` | TLS | TLS, untouched | in the **pod** (task 19) |
| `reencrypt` | TLS | new, verified TLS | Route + `destinationCACertificate` (task 27) |

`insecureEdgeTerminationPolicy`: `None` (drop HTTP), `Allow` (serve both), `Redirect` (301/302
to HTTPS). Only `edge` and `reencrypt` support it — `passthrough` supports `None` and
`Redirect` only.

## Verify

```bash
oc get route edge-app -o jsonpath='{.spec.tls.termination} {.spec.tls.insecureEdgeTerminationPolicy}{"\n"}'

curl -sk --resolve edge-app.apps-crc.testing:443:127.0.0.1 \
  -o /dev/null -w '%{http_code}\n' https://edge-app.apps-crc.testing/       # 200

curl -s --resolve edge-app.apps-crc.testing:80:127.0.0.1 \
  -o /dev/null -w '%{http_code}\n' http://edge-app.apps-crc.testing/        # 302

# confirm it's YOUR cert, not the router's wildcard
openssl s_client -connect 127.0.0.1:443 -servername edge-app.apps-crc.testing </dev/null 2>/dev/null \
  | openssl x509 -noout -subject
```

A subject of `CN=*.apps-crc.testing` means you used the router's default cert and the task
fails. It must read `CN=edge-app.apps-crc.testing`.

CRC on macOS has no wildcard DNS for `*.apps-crc.testing`, hence `--resolve`.
