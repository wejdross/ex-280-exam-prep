# Task 12 — Helm

## oc path (helm is its own CLI — there is no `oc helm`)

```bash
oc new-project ex280-t12
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update bitnami
helm install t12-nginx bitnami/nginx --set service.type=ClusterIP -n ex280-t12
```

Verified working on 2026-09-21: `charts.bitnami.com/bitnami` 302-redirects to
`repo.broadcom.com/bitnami-files`, helm follows it, the chart installs and the pod reaches
Running. The 2025 Bitnami catalogue restructuring does not break this chart.

## Values — three ways to override

```bash
helm install t12-nginx bitnami/nginx --set service.type=ClusterIP
helm install t12-nginx bitnami/nginx --set-string image.tag=1.25
helm install t12-nginx bitnami/nginx -f myvalues.yaml
```

Find out what you *can* override:

```bash
helm show values bitnami/nginx | head -60
helm show values bitnami/nginx | grep -A5 '^service:'
helm show chart bitnami/nginx
```

`helm show values` is the offline-friendly substitute for reading the chart's docs — worth the
reflex, since the exam gives you the chart but not necessarily its README.

## Lifecycle commands

```bash
helm list -n ex280-t12                       # STATUS must read 'deployed'
helm list -A                                 # every namespace
helm status t12-nginx -n ex280-t12
helm get values t12-nginx -n ex280-t12       # what overrides are in effect
helm get manifest t12-nginx -n ex280-t12     # what it actually rendered

helm upgrade t12-nginx bitnami/nginx --set replicaCount=2 -n ex280-t12
helm rollback t12-nginx 1 -n ex280-t12
helm history t12-nginx -n ex280-t12
helm uninstall t12-nginx -n ex280-t12
```

## Dry run / render without installing

```bash
helm install t12-nginx bitnami/nginx --dry-run --debug -n ex280-t12
helm template t12-nginx bitnami/nginx --set service.type=ClusterIP
```

`helm template` renders locally with no cluster contact — the equivalent of
`oc process --local` for Templates.

## Verify

```bash
helm list -n ex280-t12
oc get pods -n ex280-t12
oc get svc -n ex280-t12 -o jsonpath='{.items[0].spec.type}{"\n"}'   # ClusterIP
```

## OpenShift-specific gotcha

Many upstream charts assume they can run as a fixed UID or as root. Under `restricted-v2` they
crash-loop. The fixes, in order of preference: set the chart's `podSecurityContext`/
`containerSecurityContext` values to something OpenShift-compatible; or grant the chart's
ServiceAccount `anyuid`. Bitnami charts are generally OpenShift-friendly out of the box, which
is why this one just works.
