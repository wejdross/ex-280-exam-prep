# Task 25 — Image triggers

## oc path

```bash
oc new-project ex280-t25

oc import-image t25-app:latest \
  --from=quay.io/redhattraining/hello-world-nginx:latest --confirm

oc create deployment trigger-app \
  --image=quay.io/redhattraining/hello-world-nginx:latest --replicas=1

CNAME=$(oc get deploy trigger-app -o jsonpath='{.spec.template.spec.containers[0].name}')
oc set triggers deployment/trigger-app --from-image=t25-app:latest -c "$CNAME"
```

`--from-image` wants the **ImageStreamTag** name (`t25-app:latest`), not the registry pull spec.
`-c <container>` is mandatory — without it there is no `fieldPath` to patch.

## YAML path

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: trigger-app
  namespace: ex280-t25
  annotations:
    image.openshift.io/triggers: |
      [{"from":{"kind":"ImageStreamTag","name":"t25-app:latest"},
        "fieldPath":"spec.template.spec.containers[?(@.name==\"hello-world-nginx\")].image"}]
spec:
  ...
```

A Deployment is a plain Kubernetes object, so OpenShift can't add fields to it — hence the
annotation, which a controller watches. DeploymentConfigs and BuildConfigs use a real
`spec.triggers` field instead.

## Proof it fired

```bash
oc get deploy trigger-app -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
```

Before: `quay.io/redhattraining/hello-world-nginx:latest`
After:  `quay.io/redhattraining/hello-world-nginx@sha256:7f99ece5...`

**The tag becomes a digest.** That rewrite is the proof. Still a `:tag` = never fired.

## The registry hostname surprise

Which host appears depends on the tag's reference policy:

| `referencePolicy.type` | Resolved image |
|---|---|
| `Source` (default) | `quay.io/redhattraining/hello-world-nginx@sha256:...` |
| `Local` | `image-registry.openshift-image-registry.svc:5000/ex280-t25/t25-app@sha256:...` |

```bash
oc get istag t25-app:latest -o jsonpath='{.tag.referencePolicy.type}{"\n"}'
oc import-image t25-app:latest --from=... --confirm --reference-policy=local
```

`Local` forces pulls through the internal registry (pullthrough) — useful when the external
registry needs credentials the nodes don't have. **The digest is identical either way**, so
verify on the digest, not the hostname.

## Pausing, removing, forcing an update

```bash
oc set triggers deployment/trigger-app                                # list
oc set triggers deployment/trigger-app --manual                       # pause ("paused":true)
oc set triggers deployment/trigger-app --auto                         # resume
oc set triggers deployment/trigger-app --from-image=t25-app:latest -c app --remove

oc import-image t25-app:latest --from=<newer> --confirm               # new digest -> fires
oc import-image t25-app:latest --from=... --confirm --scheduled=true  # poll upstream
```

Re-importing an **identical** image produces the same digest, so no patch and no rollout. That
is correct behaviour, not a failure.

## Verify

```bash
oc get istag t25-app:latest -o jsonpath='{.image.metadata.name}{"\n"}'
oc get deploy trigger-app -o jsonpath='{.metadata.annotations.image\.openshift\.io/triggers}{"\n"}'
oc get deploy trigger-app -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
```
