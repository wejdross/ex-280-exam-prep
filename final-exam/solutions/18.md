# Task 18 — Image digests

## oc path

```bash
oc new-project ex280-t18

oc import-image t18-image:latest \
  --from=quay.io/redhattraining/hello-world-nginx:latest --confirm

DIGEST=$(oc get istag t18-image:latest -o jsonpath='{.image.metadata.name}')
mkdir -p work/task18 && echo "$DIGEST" > work/task18/digest.txt

oc create deployment digest-app --replicas=1 \
  --image=image-registry.openshift-image-registry.svc:5000/ex280-t18/t18-image@${DIGEST}
```

`--confirm` creates the ImageStream if it doesn't exist.

## Where the digest lives

The ImageStreamTag's `.image.metadata.name` **is** the `sha256:...` string — the Image object
is named after its own digest. Not obvious. Docs-free ways to find it:

```bash
oc describe istag t18-image:latest | head
oc get istag t18-image:latest -o yaml | head -20
oc get is t18-image -o jsonpath='{.status.tags[0].items[0].image}{"\n"}'
```

## Finding the registry address without docs

Any ImageStream carries both forms, fully assembled:

```bash
oc get is t18-image -o jsonpath='{.status.dockerImageRepository}{"\n"}'
# image-registry.openshift-image-registry.svc:5000/ex280-t18/t18-image

oc get is t18-image -o jsonpath='{.status.publicDockerImageRepository}{"\n"}'
# default-route-openshift-image-registry.apps-crc.testing/ex280-t18/t18-image
```

Nothing to memorise. Fallback: `oc get svc -n openshift-image-registry` →
`<service>.<namespace>.svc:<port>`.

`oc registry info` also prints the external route but is **deprecated** on 4.22. `oc registry
login` is the surviving half of that command group.

## The reference format

```
image-registry.openshift-image-registry.svc:5000 / ex280-t18 / t18-image @ sha256:...
└─ internal registry service ────────────────┘   └ project ┘  └ IS name ┘  └ digest ┘
```

`@sha256:...` **replaces** `:tag` — never both.

## Why pulling from the internal registry works

`oc import-image` with the default reference policy (`Source`) stores a pointer to the external
image. The pod still pulls through the internal registry because of **pullthrough**: asked for
a digest it doesn't hold, the registry fetches it from the upstream recorded in the
ImageStream. And since the pod is in the same project as the ImageStream, the `default`
ServiceAccount already has `system:image-puller` via the automatic `system:image-pullers`
rolebinding — no extra RBAC.

## YAML path

```yaml
      containers:
      - name: t18-image
        image: image-registry.openshift-image-registry.svc:5000/ex280-t18/t18-image@sha256:7f99...
```

## If the import fails

```bash
oc get is t18-image -o jsonpath='{.status.tags[*].conditions[*].message}{"\n"}'
oc describe is t18-image | tail -20
oc import-image t18-image:latest --from=quay.io/... --confirm    # retry
oc import-image t18-image --all                                  # all tags
```

## Verify

```bash
oc get istag t18-image:latest -o jsonpath='{.image.metadata.name}{"\n"}'
cat work/task18/digest.txt
oc get deployment digest-app -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
```
