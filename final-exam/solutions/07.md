# Task 07 — Non-HTTP service exposure (NodePort)

## Why not a Route

A Route is an HTTP/TLS construct — the router terminates HTTP or passes TLS through by SNI. It
has no concept of raw TCP or UDP. Non-HTTP traffic leaves the cluster only via:

| Method | Notes |
|---|---|
| `NodePort` | a port on every node, 30000–32767 by default |
| `LoadBalancer` | needs a cloud provider or MetalLB (MetalLB is named in the objectives) |
| `ExternalIP` | requires `spec.externalIP.policy` on the cluster network config |
| `hostNetwork` pod | pod binds the node's port directly; needs the `hostnetwork` SCC |

## oc path

```bash
oc new-project ex280-t07
oc apply -f solutions/yaml/07-raw-tcp.yaml
```

The Service alone, imperatively:

```bash
oc expose pod raw-tcp --type=NodePort --port=9000 --target-port=9000 --name=raw-tcp
oc patch svc raw-tcp -p '{"spec":{"ports":[{"port":9000,"targetPort":9000,"nodePort":30900}]}}'
```

`oc expose --type=NodePort` cannot pin a specific `nodePort`, so a fixed port number means
either a patch or YAML. Given the task fixes it at 30900, YAML is the cleaner route.

## YAML path (`solutions/yaml/07-raw-tcp.yaml`)

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: raw-tcp
  namespace: ex280-t07
  labels: {app: raw-tcp}
spec:
  containers:
  - name: echo
    image: registry.access.redhat.com/ubi9/python-311:latest
    command: ["python3","-c","import socketserver;socketserver.TCPServer.allow_reuse_address=True;socketserver.TCPServer(('0.0.0.0',9000),type('H',(socketserver.StreamRequestHandler,),{'handle':lambda s: s.wfile.write(s.rfile.readline())})).serve_forever()"]
    ports:
    - containerPort: 9000
---
apiVersion: v1
kind: Service
metadata:
  name: raw-tcp
  namespace: ex280-t07
spec:
  type: NodePort
  selector: {app: raw-tcp}
  ports:
  - port: 9000
    targetPort: 9000
    nodePort: 30900
```

## Verify

```bash
oc get svc raw-tcp -o jsonpath='{.spec.type} {.spec.ports[0].port}:{.spec.ports[0].nodePort}{"\n"}'
NODEIP=$(oc get node crc -o jsonpath='{.status.addresses[?(@.type=="InternalIP")].address}')
oc run probe --rm -i --image=registry.access.redhat.com/ubi9/ubi-minimal:latest --restart=Never -- \
  sh -c "echo hello | timeout 5 bash -c 'cat > /dev/tcp/$NODEIP/30900'"
```

**You cannot test this from the Mac.** `crc ip` returns `127.0.0.1` — CRC on macOS uses
user-mode networking and forwards only TCP 6443/80/443. Node IP `192.168.126.11` lives inside
the VM. Grading connects from inside the cluster for exactly this reason.

## `externalTrafficPolicy` — worth knowing even though this task doesn't ask

| Value | Source IP | Reach |
|---|---|---|
| `Cluster` (default) | SNAT'd to the node IP | any node forwards to any pod |
| `Local` | **preserved** | only nodes running a backend pod respond |

This matters the moment you combine NodePort/LoadBalancer with `sessionAffinity: ClientIP`:
under `Cluster`, every external client looks like the same IP and they all pin to one pod, so
the affinity is real but meaningless.
