# Task 23 — Users, groups and group permissions

## oc path

```bash
# carol is already in assets/htpasswd_ex280 — just refresh the Secret
oc create secret generic htpasswd-ex280 \
  --from-file=htpasswd=assets/htpasswd_ex280 -n openshift-config \
  --dry-run=client -o yaml | oc apply -f -

oc new-project ex280-t23
oc adm groups new ex280-ops alice carol
oc adm policy add-role-to-group view ex280-ops -n ex280-t23
```

`--dry-run=client -o yaml | oc apply -f -` is the idiom for replacing an existing Secret —
`oc create` alone fails with AlreadyExists.

Group management:

```bash
oc adm groups new ex280-ops alice carol
oc adm groups add-users ex280-ops bob
oc adm groups remove-users ex280-ops bob
oc get group ex280-ops
oc get groups
```

## YAML path

```yaml
apiVersion: user.openshift.io/v1
kind: Group
metadata:
  name: ex280-ops
users:
- alice
- carol
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: ex280-ops-view
  namespace: ex280-t23
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: view
subjects:
- apiGroup: rbac.authorization.k8s.io
  kind: Group          # <- Group, not User. That's the whole task.
  name: ex280-ops
```

## The trap: `--as` does not resolve group membership

Verified on this cluster:

```bash
oc auth can-i get pods -n ex280-t23 --as=alice                        # no
oc auth can-i get pods -n ex280-t23 --as=alice --as-group=ex280-ops   # yes

# but a REAL login:
oc login -u alice -p redhatB1 ...
oc auth can-i get pods -n ex280-t23                                   # yes
```

Impersonation with `--as` carries only the **username**. The OpenShift Group object is not
looked up — you must also pass `--as-group`, or log in for real. If you test a group-granted
permission with `--as` alone and see `no`, your RBAC is probably fine and your *test* is wrong.

This is why the grader for this task logs in as each user instead of impersonating.

## Users, identities and passwords

```bash
oc get users
oc get identities
oc delete user bob && oc delete identity htpasswd_ex280:bob   # both, or bob half-exists
```

Changing a password = editing the htpasswd file and replacing the Secret:

```bash
oc extract secret/htpasswd-ex280 -n openshift-config --to=. --confirm
htpasswd -bB htpasswd carol newpassword
oc set data secret/htpasswd-ex280 --from-file=htpasswd -n openshift-config
```

## Why groups instead of users

`view` bound to a group means adding a person is one `oc adm groups add-users` instead of a new
RoleBinding per project per person. The exam objective is literally *"Create and manage
groups"* and *"Modify user and group permissions"* — expect to be asked for the group form
specifically, and binding the users individually will fail it.
