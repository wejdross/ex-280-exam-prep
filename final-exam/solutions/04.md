# Task 04 — Deployment with probes and resources

## oc path

```bash
oc new-project ex280-t04
oc create deployment webapp \
  --image=quay.io/redhattraining/hello-world-nginx:latest --replicas=2

oc set resources deployment/webapp \
  --requests=cpu=100m,memory=128Mi --limits=cpu=250m,memory=256Mi

oc set probe deployment/webapp --readiness --get-url=http://:8080/
oc set probe deployment/webapp --liveness  --open-tcp=8080

oc expose deployment webapp --port=8080 --target-port=8080 --name=webapp
```

`oc set probe` is the command people forget exists and then hand-edit YAML for. Its three forms:

| Flag | Probe type |
|---|---|
| `--get-url=http://:8080/path` | HTTP GET (note the empty host — means "the pod") |
| `--open-tcp=8080` | TCP socket |
| `-- cat /tmp/healthy` | exec |

Tuning flags: `--initial-delay-seconds`, `--period-seconds`, `--timeout-seconds`,
`--failure-threshold`, `--success-threshold`.

## YAML path

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: webapp
  namespace: ex280-t04
  labels: {app: webapp}
spec:
  replicas: 2
  selector:
    matchLabels: {app: webapp}
  template:
    metadata:
      labels: {app: webapp}
    spec:
      containers:
      - name: hello-world-nginx
        image: quay.io/redhattraining/hello-world-nginx:latest
        ports:
        - containerPort: 8080
        resources:
          requests: {cpu: 100m, memory: 128Mi}
          limits:   {cpu: 250m, memory: 256Mi}
        readinessProbe:
          httpGet: {path: /, port: 8080}
        livenessProbe:
          tcpSocket: {port: 8080}
---
apiVersion: v1
kind: Service
metadata:
  name: webapp
  namespace: ex280-t04
spec:
  selector: {app: webapp}
  ports:
  - port: 8080
    targetPort: 8080
```

## Readiness vs liveness — the distinction the exam wants

- **Readiness** failing → pod removed from Service endpoints, kept running. For "not ready yet".
- **Liveness** failing → container **killed and restarted**. For "wedged, needs a kick".

A liveness probe with too short an `initialDelaySeconds` on a slow-starting app produces an
infinite restart loop. That is the classic misconfiguration.

## Verify

```bash
oc get deployment webapp -o jsonpath='{.status.readyReplicas}/{.spec.replicas}{"\n"}'
oc set probe deployment/webapp            # lists current probes
oc set resources deployment/webapp        # lists current resources
oc get endpoints webapp
```
