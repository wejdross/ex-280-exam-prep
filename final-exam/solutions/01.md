# Task 01 — HTPasswd identity provider

## oc path

```bash
oc create secret generic htpasswd-ex280 \
  --from-file=htpasswd=assets/htpasswd_ex280 -n openshift-config

oc patch oauth cluster --type=json -p '[{"op":"add","path":"/spec/identityProviders/-","value":{
  "name":"htpasswd_ex280","mappingMethod":"claim","type":"HTPasswd",
  "htpasswd":{"fileData":{"name":"htpasswd-ex280"}}}}]'
```

`op: add` with path `/spec/identityProviders/-` **appends**. That matters: the task forbids
removing the pre-existing `developer` provider, and `oc edit`/`--type=merge` on a list replaces
it wholesale.

If `spec.identityProviders` does not exist yet, the `-` append fails; seed it first with
`--type=merge -p '{"spec":{"identityProviders":[]}}'`.

## YAML path

```yaml
apiVersion: config.openshift.io/v1
kind: OAuth
metadata:
  name: cluster
spec:
  identityProviders:
  - name: developer          # keep whatever was already here
    mappingMethod: claim
    type: HTPasswd
    htpasswd:
      fileData:
        name: <existing secret>
  - name: htpasswd_ex280
    mappingMethod: claim
    type: HTPasswd
    htpasswd:
      fileData:
        name: htpasswd-ex280
```

```bash
oc apply -f oauth.yaml
```

## Adding a user later (task 23)

The htpasswd file lives in a Secret; edit the file and replace the Secret:

```bash
oc extract secret/htpasswd-ex280 -n openshift-config --to=. --confirm
htpasswd -bB htpasswd carol redhatB1
oc set data secret/htpasswd-ex280 --from-file=htpasswd -n openshift-config
```

`assets/htpasswd_ex280` already contains alice, bob and carol, so for this exam you just
create the Secret from it once.

Changing a password is the same operation; deleting a user is `htpasswd -D htpasswd bob`
followed by `oc delete user bob` and `oc delete identity htpasswd_ex280:bob`.

## Verify

```bash
oc get oauth cluster -o jsonpath='{.spec.identityProviders[*].name}{"\n"}'
oc get co authentication          # wait: Available=True, Progressing=False
oc login -u alice -p redhatB1 https://api.crc.testing:6443 --insecure-skip-tls-verify=true
oc whoami
```

The oauth-openshift pods redeploy after the patch — logins fail with "Login failed (401
Unauthorized)" until that finishes. Wait for `oc get co authentication` to settle before
concluding anything is wrong. This is the single most common false alarm on this task.
