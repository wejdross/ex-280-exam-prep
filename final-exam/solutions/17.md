# Task 17 — Resource queries

## oc path

```bash
oc new-project ex280-t17
for p in q1 q2 q3 q4; do
  oc run $p -n ex280-t17 --image=registry.access.redhat.com/ubi9/ubi-minimal:latest \
    --command -- sleep 3600
done
oc label pod q1 q2 tier=frontend
oc label pod q3 q4 tier=backend

mkdir -p work/task17
oc get pods -l tier=frontend \
  -o jsonpath='{range .items[*]}{.metadata.name}{" "}{end}' \
  | sed 's/ $//' > work/task17/frontend-names.txt
```

**`-n <ns>` must come before `--`.** `oc run p --command -- sleep 3600 -n ex280-t17` passes
`-n ex280-t17` to `sleep`, which then exits non-zero and the pod crash-loops. Cost me a pod on
this run.

## The query forms worth having in your fingers

```bash
# selectors
oc get pods -l tier=frontend
oc get pods -l 'tier in (frontend,backend)'
oc get pods -l '!tier'                      # pods with no tier label at all
oc get pods -l tier=frontend,app=web        # comma = AND

# jsonpath
oc get pods -o jsonpath='{.items[*].metadata.name}'
oc get pods -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.phase}{"\n"}{end}'
oc get pods -o jsonpath='{.items[?(@.status.phase=="Running")].metadata.name}'

# custom-columns
oc get pods -o custom-columns=NAME:.metadata.name,TIER:.metadata.labels.tier
oc get pods -o custom-columns=NAME:.metadata.name --no-headers

# sorting and the wide view
oc get pods --sort-by=.metadata.creationTimestamp
oc get pods -o wide
oc get pods -A                              # all namespaces
```

`{range ...}{end}` is the construct to memorise — without it you get everything on one line
with no separators.

Escaping a dotted key needs a backslash:

```bash
oc get deploy x -o jsonpath='{.metadata.annotations.image\.openshift\.io/triggers}'
```

## Labelling

```bash
oc label pod q1 tier=frontend
oc label pod q1 tier=backend --overwrite     # required to change an existing label
oc label pod q1 tier-                        # trailing dash removes
oc label pods --all env=exam
```

## YAML path

Not applicable — this task is a query exercise. The pods themselves can of course be YAML:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: q1
  labels:
    tier: frontend
spec:
  containers:
  - name: c
    image: registry.access.redhat.com/ubi9/ubi-minimal:latest
    command: ["sleep","3600"]
```

## Verify

```bash
oc get pods --show-labels
cat work/task17/frontend-names.txt     # q1 q2
```

## A note on this task's shape

"Query, format, and filter attributes of Kubernetes resources" is a genuine EX280 objective, so
the skill belongs here. The *file deliverable* and the `command.txt` check are artefacts of
making it auto-gradeable — the real exam grades cluster state and never inspects which command
you typed. Practise the queries; don't read the file-writing part as exam-realistic.
