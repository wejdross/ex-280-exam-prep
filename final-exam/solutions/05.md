# Task 05 — Security context constraints

## oc path

```bash
oc new-project ex280-t05
oc create sa root-runner
oc adm policy add-scc-to-user anyuid -z root-runner
```

`-z` means "serviceaccount in the current project". The long form is
`add-scc-to-user anyuid system:serviceaccount:ex280-t05:root-runner`.

Then the pod (`solutions/yaml/05-root-pod.yaml`):

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: root-pod
  namespace: ex280-t05
spec:
  serviceAccountName: root-runner
  containers:
  - name: root
    image: registry.access.redhat.com/ubi9/ubi-minimal:latest
    command: ["sleep","3600"]
    securityContext:
      runAsUser: 0
```

```bash
oc apply -f solutions/yaml/05-root-pod.yaml
```

## The trap this task is built around

You are `kubeadmin`, who may use **every** SCC. So a pod you create by hand runs as root
whether or not the ServiceAccount is authorised — the pod "works" while the actual requirement
is unmet. The grader therefore checks the **ServiceAccount's** permissions, not just the pod.

Test the SA, not yourself:

```bash
oc auth can-i use scc/anyuid     --as=system:serviceaccount:ex280-t05:root-runner   # yes
oc auth can-i use scc/privileged --as=system:serviceaccount:ex280-t05:root-runner   # no
```

## SCCs worth knowing cold

| SCC | Grants |
|---|---|
| `restricted-v2` | default; random UID, no privileges, drops ALL caps |
| `nonroot-v2` | any UID the image asks for, except 0 |
| `anyuid` | any UID **including 0**; no other privilege |
| `hostmount-anyuid` | anyuid + host volume mounts |
| `hostnetwork-v2` | host network/ports |
| `privileged` | everything — the sledgehammer |

"needs to run as root and nothing else" → **`anyuid`**. Granting `privileged` fails this task
explicitly.

## Which SCC actually got used

```bash
oc get pod root-pod -o jsonpath='{.metadata.annotations.openshift\.io/scc}{"\n"}'
oc get pod root-pod -o jsonpath='{.spec.containers[0].securityContext.runAsUser}{"\n"}'
```

## Removing / auditing

```bash
oc adm policy remove-scc-from-user anyuid -z root-runner
oc adm policy who-can use scc/anyuid
oc describe scc anyuid
```
