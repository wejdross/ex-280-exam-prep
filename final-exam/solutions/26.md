# Task 26 — Project template and cluster quota

## Part A — project request template

```bash
oc adm create-bootstrap-project-template -o yaml > project-request.yaml
```

**Never write this from scratch.** The built-in template contains the RoleBindings that make a
project usable; omitting them creates projects their owner can't use.

Rename it and append the LimitRange:

```yaml
metadata:
  name: project-request
objects:
# ... the built-in Project + RoleBindings, left alone ...
- apiVersion: v1
  kind: LimitRange
  metadata:
    name: default-limits
    namespace: ${PROJECT_NAME}
  spec:
    limits:
    - type: Container
      defaultRequest: {cpu: 100m, memory: 128Mi}
      default:        {cpu: 500m, memory: 512Mi}
```

```bash
oc apply -f project-request.yaml -n openshift-config
oc patch project.config.openshift.io/cluster --type=merge \
  -p '{"spec":{"projectRequestTemplate":{"name":"project-request"}}}'
```

The template **must** live in `openshift-config`. The config object is
`project.config.openshift.io/cluster` — not a `Project`.

## The time sink

That patch restarts the **openshift-apiserver**. For several minutes:

```
error: the server doesn't have a resource type "template"
```

Worse, on this run the operator briefly reported `Available=True, Progressing=False` **before**
the rollout actually began — so a single check is not enough. Sample it a few times:

```bash
oc get co openshift-apiserver
oc get templates.template.openshift.io -n openshift-config    # the real readiness test
```

Budget 3–5 minutes. Don't conclude the template is wrong during that window.

## Part B — ClusterResourceQuota

```bash
oc create clusterresourcequota ex280-crq \
  --project-annotation-selector=openshift.io/requester=alice \
  --hard=pods=10 --hard=memory=4Gi
```

```yaml
apiVersion: quota.openshift.io/v1
kind: ClusterResourceQuota
metadata:
  name: ex280-crq
spec:
  selector:
    annotations:
      openshift.io/requester: alice
  quota:
    hard:
      pods: "10"
      memory: 4Gi
```

Or by project label:

```bash
oc create clusterresourcequota team-crq \
  --project-label-selector=team=platform --hard=pods=50
```

## ResourceQuota vs ClusterResourceQuota

| | ResourceQuota (task 09) | ClusterResourceQuota (this) |
|---|---|---|
| Scope | one namespace | **aggregate across selected projects** |
| API | `v1` | `quota.openshift.io/v1` |
| Targeting | the namespace it lives in | label or annotation selector |

The objectives list "cluster resource quotas" and "project quotas" separately, on purpose.

`openshift.io/requester` is set on projects created **by a user** via `new-project`. A project
created by an admin with `oc create ns` has no requester annotation and will never match.

## Verify

```bash
oc get project.config.openshift.io/cluster -o jsonpath='{.spec.projectRequestTemplate.name}{"\n"}'
oc get templates.template.openshift.io project-request -n openshift-config

oc new-project probe-test && oc get limitrange -n probe-test && oc delete project probe-test

oc get clusterresourcequota ex280-crq -o jsonpath='{.spec.selector}{"\n"}'
oc describe clusterresourcequota ex280-crq | sed -n '/Namespaces/,$p'
```

A CRQ whose selector matches nothing exists happily and enforces nothing — always check
`status.namespaces`.
