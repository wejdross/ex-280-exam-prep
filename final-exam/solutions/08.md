# Task 08 — NetworkPolicy

## oc path

There is no `oc create networkpolicy`. This one is hand-written — but the workloads are not:

```bash
oc new-project ex280-t08
for d in frontend backend other; do
  oc create deployment $d --image=quay.io/redhattraining/hello-world-nginx:latest --replicas=1
  oc expose deployment $d --port=8080 --target-port=8080 --name=$d
done
oc apply -f solutions/yaml/08-netpol.yaml
```

`oc create deployment X` labels the pods `app=X` automatically — which is what the policy
selects on, so no extra labelling step is needed.

## YAML path (`solutions/yaml/08-netpol.yaml`)

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: backend-allow-frontend
  namespace: ex280-t08
spec:
  podSelector:              # WHO this policy protects
    matchLabels:
      app: backend
  policyTypes: ["Ingress"]
  ingress:
  - from:
    - podSelector:          # WHO is allowed in
        matchLabels:
          app: frontend
    ports:
    - protocol: TCP
      port: 8080
```

## The mental model that prevents most mistakes

1. Pods are **unrestricted** until some policy selects them.
2. The moment **any** policy selects a pod, that pod becomes **default-deny** for the listed
   `policyTypes`, and only the union of matching rules is allowed.
3. Policies are **additive** — there is no "deny" rule. You cannot write "block other"; you
   write "allow frontend", and everything else is denied as a consequence.

This is why the task says "nothing else about default connectivity should be affected": the
policy selects only `app=backend`, so `frontend` and `other` keep talking to everything else.
A blanket default-deny across the namespace would over-shoot.

## The `from` selectors, and the comma trap

```yaml
  # OR — two separate list items
  - from:
    - podSelector: {matchLabels: {app: frontend}}
    - namespaceSelector: {matchLabels: {kubernetes.io/metadata.name: other-ns}}

  # AND — one item with two keys: a pod labelled app=frontend IN that namespace
  - from:
    - podSelector: {matchLabels: {app: frontend}}
      namespaceSelector: {matchLabels: {kubernetes.io/metadata.name: other-ns}}
```

One dash = one rule. The indentation difference between OR and AND is a single character and
it changes the meaning completely.

## Verify

```bash
oc exec deploy/frontend -- curl -s -o /dev/null -w '%{http_code}\n' --max-time 5 http://backend:8080   # 200
oc exec deploy/other    -- curl -s -o /dev/null -w '%{http_code}\n' --max-time 5 http://backend:8080   # timeout/000
oc describe networkpolicy backend-allow-frontend
```

A blocked connection **hangs then times out** — it does not return a clean refusal. Always use
`--max-time`, or you will sit there wondering.

## Two patterns worth memorising

```yaml
# default-deny all ingress in a namespace
spec:
  podSelector: {}
  policyTypes: ["Ingress"]
```
```yaml
# allow the OpenShift router in (needed if you default-deny and still want Routes to work)
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          policy-group.network.openshift.io/ingress: ""
```
