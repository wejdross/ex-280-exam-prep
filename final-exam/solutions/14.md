# Task 14 — Operator installation via OLM

## oc path

```bash
oc apply -f solutions/yaml/14-subscription.yaml
```

A Subscription is the whole install. There is no `oc create subscription` generator, so this is
a YAML task — but a three-field one.

## YAML (`solutions/yaml/14-subscription.yaml`)

```yaml
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: rh-service-binding-operator
  namespace: openshift-operators
spec:
  name: rh-service-binding-operator      # the PACKAGE name
  source: redhat-operators               # the CatalogSource
  sourceNamespace: openshift-marketplace
  channel: stable
  installPlanApproval: Automatic
```

## Finding the four values without docs

Everything you need is in the PackageManifest:

```bash
oc get packagemanifest -n openshift-marketplace | grep -i service-binding
oc get packagemanifest rh-service-binding-operator -n openshift-marketplace \
  -o jsonpath='{.status.defaultChannel}{"\n"}'
oc get packagemanifest rh-service-binding-operator -n openshift-marketplace \
  -o jsonpath='{range .status.channels[*]}{.name}{"\n"}{end}'
oc get packagemanifest rh-service-binding-operator -n openshift-marketplace \
  -o jsonpath='{.status.catalogSource}/{.status.catalogSourceNamespace}{"\n"}'
```

Confirmed present on this cluster's catalogue snapshot.

## AllNamespaces vs a single namespace

Installing into `openshift-operators` gives cluster-wide (AllNamespaces) scope — that namespace
already has a global OperatorGroup, so **you do not create one**.

For a single-namespace install you must create both:

```yaml
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: my-og
  namespace: my-operators
spec:
  targetNamespaces:
  - my-operators
```

Forgetting the OperatorGroup is the #1 reason a single-namespace operator install hangs
forever with no obvious error.

## Watching the install

```bash
oc get subscription -n openshift-operators
oc get installplan -n openshift-operators
oc get csv -n openshift-operators -w        # wait for PHASE=Succeeded
```

Result on this run: `service-binding-operator.v1.3.3  Succeeded`.

With `installPlanApproval: Manual`, the InstallPlan sits unapproved until:

```bash
oc patch installplan <name> -n openshift-operators --type=merge -p '{"spec":{"approved":true}}'
```

## Deleting an operator (also an objective)

```bash
oc delete subscription rh-service-binding-operator -n openshift-operators
oc delete csv service-binding-operator.v1.3.3 -n openshift-operators
```

Deleting only the Subscription leaves the CSV — and therefore the operator — running. Both
must go. Any CRDs it installed are cluster-scoped and survive both; remove them separately if
you want a clean slate.

## Verify

```bash
oc get csv -n openshift-operators
oc get csv -n openshift-operators -o jsonpath='{.items[0].status.phase}{"\n"}'
```
