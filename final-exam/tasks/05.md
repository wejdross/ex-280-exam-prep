# Task 05 — Security context constraints (15 points)

In project `ex280-t05` (create it if it doesn't exist), a container image requires running as
UID `0` (root) to function correctly.

- Create a ServiceAccount named `root-runner` in that project.
- Grant **that ServiceAccount** exactly the privilege it needs to run as root — no more. It must
  be authorized to use `anyuid`, and it must NOT be authorized to use `privileged`.
  (Note: you are logged in as `kubeadmin`, who may use every SCC, so a pod you create by hand
  runs as root whether or not the ServiceAccount is authorized. Grading therefore checks the
  ServiceAccount's own permissions, not just the pod.)
- Deploy a Pod named `root-pod` using image `registry.access.redhat.com/ubi9/ubi-minimal:latest`
  with command `["sleep", "3600"]`, running as UID `0`, using that ServiceAccount.
- The pod must reach `Running` state.

Your solution will be verified by checking the pod's status, its ServiceAccount, its effective
UID, the SCC applied to it, and whether the ServiceAccount itself may use `anyuid` (yes) and
`privileged` (no).
