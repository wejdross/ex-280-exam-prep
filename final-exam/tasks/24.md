# Task 24 — StatefulSet with non-shared storage (15 points)

In project `ex280-t24` (create it if it doesn't exist):

- Create a **headless** Service named `t24-db` (clusterIP `None`) on port `8080`, selecting
  `app=t24-db`.
- Create a StatefulSet named `t24-db` with:
  - `serviceName: t24-db`,
  - 2 replicas,
  - image `registry.access.redhat.com/ubi9/ubi-minimal:latest`,
  - a `volumeClaimTemplate` named `data` requesting `1Gi`, access mode `ReadWriteOnce`, from
    the cluster's default StorageClass, mounted at `/data`,
  - a container command that writes its own pod name into `/data/id.txt` once and then sleeps,
    so each replica's volume ends up holding a **different** value. Copy this verbatim:

    ```yaml
    command: ["sh","-c","echo $HOSTNAME > /data/id.txt; sleep 3600"]
    ```

- Both pods must reach Running.

Your solution will be verified by checking that two separate PVCs exist (`data-t24-db-0` and
`data-t24-db-1`), that both are Bound, that the Service is headless, and — the actual point of
the task — that `/data/id.txt` inside pod `t24-db-0` reads `t24-db-0` and inside `t24-db-1`
reads `t24-db-1`, proving the storage is per-pod and not shared.
