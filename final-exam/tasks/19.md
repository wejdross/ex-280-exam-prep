# Task 19 — Non-HTTP passthrough / TLS backend (15 points)

In project `ex280-t19` (create it if it doesn't exist):

- Use the certificate and key already provided at `assets/tls-app/tls.crt` and
  `assets/tls-app/tls.key` (RSA 2048, subject `CN=tls-app.apps-crc.testing`, valid until 2036)
  and store them in a TLS Secret named `tls-app-cert` in this project. **Do not run
  `openssl`** — the real exam hands you the cert files.
- Deploy `tls-app`, 1 replica, image `registry.access.redhat.com/ubi9/python-311:latest`, with
  the Secret mounted at `/etc/tls`, whose container terminates TLS itself on port `8443` by
  running exactly this command (copy it verbatim):

  ```yaml
  command: ["python3","-c","import http.server,ssl;ctx=ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER);ctx.load_cert_chain('/etc/tls/tls.crt','/etc/tls/tls.key');s=http.server.HTTPServer(('0.0.0.0',8443),http.server.SimpleHTTPRequestHandler);s.socket=ctx.wrap_socket(s.socket,server_side=True);s.serve_forever()"]
  ```

- Create a Service named `tls-app` on port `8443` (targetPort `8443`).
- Create a Route named `tls-app` with `passthrough` termination, hostname
  `tls-app.apps-crc.testing`, pointing at that Service.

Your solution will be verified by checking the Route's termination type and backing Service
port, that an HTTPS request to the hostname completes (self-signed/untrusted is fine), and that
the certificate presented on `:443` has subject `CN=tls-app.apps-crc.testing` — i.e. the pod's
own cert passed through, not the router's wildcard.

Note: `crc` on macOS has no wildcard DNS for `*.apps-crc.testing`. Grading resolves the hostname
itself; if you want to test the route by hand, add `127.0.0.1 tls-app.apps-crc.testing` to
`/etc/hosts` or use `curl --resolve tls-app.apps-crc.testing:443:127.0.0.1 ...`.
