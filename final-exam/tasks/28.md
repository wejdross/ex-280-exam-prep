# Task 28 — Application access to the Kubernetes API (15 points)

In project `ex280-t28` (create it if it doesn't exist):

- Create a ServiceAccount named `api-reader`.
- Grant it exactly enough permission to **list pods in `ex280-t28` only** — `get`, `list` and
  `watch` on pods, nothing more, and nothing outside this project.
- Deploy a Pod named `api-client` using image
  `registry.access.redhat.com/ubi9/ubi-minimal:latest`, command `["sleep","3600"]`, running
  under that ServiceAccount.
- The application must be able to call the Kubernetes API **using its own mounted
  ServiceAccount token** — you do not need to create or paste any token yourself.

Your solution will be verified from inside `api-client`: a request to
`https://kubernetes.default.svc/api/v1/namespaces/ex280-t28/pods` using the pod's own
projected token and the cluster CA must return HTTP 200 and a `PodList`, while the same
request against another namespace's pods must return HTTP 403. The ServiceAccount must also
not be able to list secrets.
